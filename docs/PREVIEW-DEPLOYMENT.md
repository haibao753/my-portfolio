## Workers Builds settings

Use an explicit Build command, as described in Cloudflare's [Workers Builds configuration documentation](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/). The installed Wrangler CLI can still invoke a custom build from the Preview command, so do not rely on that documentation note to bypass or verify the CLI build guard.

| Setting | Production (preserved) | Preview Base |
| --- | --- | --- |
| Build command | `npm run build` | `npm run build:cloudflare` |
| Deploy / Preview command | `npx wrangler deploy --config wrangler.production.jsonc` | `npx wrangler preview --config wrangler.branch-preview.jsonc` |
| Root directory | `/` | `/` |
| Production branch | `main` | feature branches |

`build:cloudflare` fetches the published news ref, synchronizes JSON and runs the production Astro build. It never uploads or deploys. The direct Wrangler CLI custom-build entry remains guarded. Do not infer dashboard success from its local dry-run.

Authenticated logs for build `93a85ac4` confirmed that the dashboard Build command was empty and `npx wrangler preview` failed because the root configuration lacked a `previews` block. The root configuration now includes an empty block, as required by the [Preview configuration documentation](https://developers.cloudflare.com/workers/previews/configuration/#wrangler-configuration-file). Assets remain at the top level; no production data bindings or routes are added to the Preview.

Build `7e499e6c` then reached the root custom build but tripped the production guard. Inspection of the installed Wrangler 4.151.0 CLI confirmed that its Preview handler calls `getEntry(..., "deploy")`, which sets `WRANGLER_COMMAND=deploy` even for a Preview. `wrangler.branch-preview.jsonc` therefore supplies the same existing Worker name and static assets without a custom build. The explicit dashboard build generates assets first; `wrangler preview` creates only the branch Preview. The guarded root configuration and production deploy configuration remain separate and unchanged in behavior.

## Dedicated preview Worker

The checked-in `wrangler.preview.jsonc` deliberately names **`jhlab-preview`**, does not contain any production domain or routes, and serves `./dist` as Workers Static Assets.

The static site is generated by Astro. On the refactor branch:

```sh
npm install
git fetch origin main
node scripts/sync-news-preview.mjs
npm run check
npm run build
npm run test:e2e
npm run deploy:preview:dry-run
```

To create the separate preview Worker when Cloudflare authentication is ready:

```sh
npm run deploy:preview
```

The first real deployment normally requires Cloudflare authorization and permissions. Never paste an API token or account identifier into ChatGPT, GitHub source files or screenshots. Do not copy the production token into another repository.

Expected preview address is normally `https://jhlab-preview.<your-workers-subdomain>.workers.dev`, **only if the deployment succeeds and Workers subdomain routing is active**. Do not assume that URL is already live. Copy the actual deployed URL from Wrangler or the Cloudflare dashboard.

### Cloudflare dashboard alternative

If setting up Git-connected builds via the Cloudflare dashboard, **create a separate Worker named `jhlab-preview`**. Connect only the refactor branch, not the live `my-portfolio` Worker. Configure:

- Git repository: `haibao753/my-portfolio`
- Production branch for the *new preview Worker only*: `refactor/astro-foundation`
- Root: `/`
- Build command: `git fetch --depth=1 origin main && node scripts/sync-news-preview.mjs && npm run build`
- Deploy command: `npx wrangler deploy --config wrangler.preview.jsonc`
- Node.js: 22 or compatible version
- Never attach `hujinhai.com` to the preview Worker.

This approach should be checked against Cloudflare's current build environment before making any UI changes.

## CI safeguards and artifacts

### Default Workers command and branch protection

The root wrangler.jsonc explicitly selects the existing my-portfolio Worker and
static dist assets, so Wrangler no longer guesses the jh-lab package name or an
Astro SSR Worker entry point. Direct CLI custom builds accept preview/version uploads.
Default wrangler deploy is permitted only when the deployment branch is main,
following the owner's explicit approval. Unknown/feature branches fail closed.

The separate wrangler.preview.jsonc still deploys only jhlab-preview. Cloudflare
Pages keeps using its dashboard configuration (no pages_build_output_dir is
declared in the root Workers config).

Reproduced before this repair: the default deployment command entered Astro
auto-configuration and failed with Missing entry-point to Worker script or to
assets directory. This reproduction is evidence of a source configuration
defect; Cloudflare's detailed remote failure must still be checked independently.

GitHub Actions fetches the latest publicly published `main` news JSON **inside the runner only** before building, then validates Astro, existing routes, desktop and mobile Chromium UX and a Wrangler **dry-run**. It uploads a complete static `dist/` artifact, screenshots and traces. A dry-run validates the upload shape but does **not** deploy, guarantee permissions, or produce a preview URL.

Latest runs and artifacts: https://github.com/haibao753/my-portfolio/actions
